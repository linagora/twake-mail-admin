## Context

linagora/twake-mail-admin#160: the Twake Mail Admin console searches a dead-lettered event with `GET /events/deadLetter?eventId=...`. WebAdmin returns the event location in the `X-Group` and `X-Insertion-Id` response headers.

The console runs on a different origin than the proxy. Browsers hide non-safelisted response headers from cross-origin JavaScript unless they are listed in `Access-Control-Expose-Headers`. `WebAdminProxy#addCorsHeaders` sets `Access-Control-Allow-Origin`, `-Methods`, `-Headers` and `-Credentials`, but not `Access-Control-Expose-Headers`. So the console always shows "Group: N/A" / "Insertion ID: N/A".

## Desired CORS control

When CORS headers are added (`corsAllowOrigins` is non-empty and the request has an `Origin`), also send:

```
Access-Control-Expose-Headers: X-Group, X-Insertion-Id
```

This should be set on actual responses as well as preflight responses, since browsers read it from the actual response. Possible improvement: make the list configurable (e.g. a `cors.expose.headers` setting) and default it to the headers that WebAdmin clients need, starting with `X-Group, X-Insertion-Id`.

## Acceptance

- An integration test in `WebAdminProxyIntegrationTest` checks that a cross-origin `GET /events/deadLetter?eventId=...` response includes `Access-Control-Expose-Headers` listing `X-Group` and `X-Insertion-Id`, and that the upstream `X-Group` / `X-Insertion-Id` headers are forwarded.
